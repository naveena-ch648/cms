# Implementation Plan: File Upload & Storage System

**Branch**: `003-file-upload-storage` | **Date**: 2026-05-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/003-file-upload-storage/spec.md`

## Summary

Build a complete file upload and storage system using MinIO (S3-compatible) for object storage, Spring Boot upload APIs with chunked upload support, Redis queues for async processing dispatched to Python workers, and MySQL for file metadata storage. The system supports drag-and-drop UI uploads, programmatic API uploads, resumable chunked uploads for large files, file download/preview, and full file lifecycle management (rename, move, copy, trash, restore, permanent delete).

## Technical Context

**Language/Version**: Java 17 (Spring Boot 3.3.5 backend), Python 3.11 (workers), TypeScript 5.6 (React 18 frontend)  
**Primary Dependencies**: Spring Boot 3.3.5, AWS S3 SDK v2 (for MinIO), Spring Data JPA, Spring Data Redis, Apache Tika, React 18, Axios; Python: redis-py, boto3, Pillow, python-magic  
**Storage**: MySQL 8.0 (file metadata, quotas), MinIO (file content, thumbnails), Redis 7 (upload sessions, job queue)  
**Testing**: JUnit 5 + Spring Boot Test (backend), pytest (Python workers), Vitest (frontend — future)  
**Target Platform**: Docker Compose (local dev), Linux containers (production)  
**Project Type**: Web service (multi-tier: API + workers + object storage)  
**Performance Goals**: < 200ms API response for metadata ops, < 5s for file listing with thumbnails, 100 concurrent uploads  
**Constraints**: Max 10 GB file size, 24h upload session TTL, 30-day default trash retention  
**Scale/Scope**: Multi-tenant, org-level quotas, folder-level permissions
