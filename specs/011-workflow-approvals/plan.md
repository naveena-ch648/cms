# Implementation Plan: Document Workflow & Approvals Engine

**Branch**: `011-workflow-approvals` | **Date**: 2026-05-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/011-workflow-approvals/spec.md`

## Summary

Build a document lifecycle workflow engine supporting the state machine Draft → Review → Approved → Published → Archived. Implements approval requests with multi-reviewer consensus, event-driven triggers (notifications and prerequisites), and full transition audit history. Uses enum-based state machine (no Spring State Machine framework), separate approval_requests/approval_decisions tables, and DB-stored triggers with synchronous execution.

## Technical Context

**Language/Version**: Java 17 (Spring Boot 3.3.5 backend), TypeScript 5.6 (React 18 frontend)  
**Primary Dependencies**: Spring Data JPA, Spring Security, Spring Data Redis, jjwt 0.12.6, React 18, React Router 6.28, Axios 1.7.7, Vite 6  
**Storage**: MySQL 8.0 (port 3307, root/root) with Flyway migrations (next: V18), Redis 7 (port 6379) for notification counts  
**Testing**: JUnit 5, Mockito (backend); Vitest (frontend)  
**Target Platform**: Docker Compose (local dev), Linux server (prod)  
**Project Type**: Web application (multi-tenant CMS)  
**Performance Goals**: < 200ms for state transitions (p95), < 500ms for search queries (p95)  
**Constraints**: All transitions transactional, approval auto-transition within same DB transaction  
**Scale/Scope**: Multi-tenant, multi-workspace, existing file management with 10+ entities
